
## Key Concepts

1. Plan mode: for complex tasks involving large-scale changes, multiple valid approaches, architectural decisions, and multi-file modification.
Examples: restructuring a monolith into microservices, library migration affecting 45+ files, choosing between integration approaches with different infrastructure requirements.
Plan mode enables safe codebase exploration and design before committing to changes.
Claude reads and analyses without modifying files.

2. Direct execution: for well-understood changes with clear, limited scope.
Examples: single-file bug fix with clear stack trace, adding a date validation conditional, any change where the correct approach is already known.
No need to explore or design first.

3. The Explore Subagent: isolates verbose discovery output from the main conversation.
Returns summaries to preserve main conversation context.
Use during multi-phase tasks to prevent context window exhaustion.
Without it, exploration output fills the context and degrades subsequent responses.

4. Hybrid approach (plan then execute): plan mode for investigation and design, then direct execution for implementing the planned approach.
This is common in practice and tested on the exam.
Start with plan to understand and decide, then switch to direct execution to implement.
This is plan THEN direct, not plan or direct.

5. Decision framework: the choice is about ambiguity, not difficulty.
	1. A difficult but well-defined bug fix (clear stack trace, single function, known cause) is direct execution.
	2. A seemingly simple feature request with multiple valid approaches affecting multiple modules is plan mode.

6. Recognising complexity upfront: when the requirements already state complexity (e.g., restructure the monolith), plan mode should be choses immediately.
	1. Do not start with direct execution and switch to plan only if complexity emerges.

## Anti-Patterns

- Using direct execution for architectural decisions without exploring first.
- Using plan mode for simple, well-understood bug fixes (wastes time).
- Not using the Explore subagent for verbose discovery, causing context window exhaustion.
- Ignoring the hybrid approach and treating plan/direct as mutually exclusive.
- Starting direct execution and switching to plan only when complexity emerges (when complexity was already stated)

## Exam Traps

- Multi-file modification (10+ files) with multiple valid approaches require plan mode.
- A single-file bug fix with a clear stack trace does NOT need plan mode.
- The exam tests whether you know the hybrid pattern: plan THEN direct.
- When complexity is stated in requirements, choose plan mode upfront.
