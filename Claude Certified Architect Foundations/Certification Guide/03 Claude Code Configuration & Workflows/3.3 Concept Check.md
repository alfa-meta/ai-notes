
## Key Concepts

1. .claude/rules/ files with YAML frontmatter: Rule files in .claude/rules/ include a paths field in their YAML frontmatter specifying glob patterns.
	1. Rules only load when editing files that match those glob patterns.
	2. Example: paths: `["terraform/**/*"]` loads only when editing Terraform files.
2. Glob patterns match across the ENTIRE codebase: `**/*.test.tsx` catches every test file regardless of which directory it sits in.
	1. This is the critical advantage over directory-level CLAUDE.md files.
3. Token efficiency: Path-scoped rules load ONLY when editing matching files.
	1. This reduces irrelevant context and token usage compare to always-loaded instructions in root CLAUDE.md.
	2. Rules about Terraform conventions do not consume tokens when editing React components.
4. Path-specific rules vs directory-level CLAUDE.md: Directory-level CLAUDE.md applies to files in one directory only.
	1. For conventions that must apply to files spread throughout many directories (like test files co-located with source files), path-specific rules with glob patterns are the correct solution.
	2. You would need a CLAUDE.md in every single directory to achieve the same effect.
5. Path-specific rules vs root CLAUDE.md: Root CLAUDE.md loads for every session regardless of what files you edit.
	1. Path-specific rules load only for matching files, making them more token-efficient.
6. Path-specific rules vs skills: Both can auto-activate via a paths frontmatter, but they serve different purposes.
	1. Rules are always-in-context guidance - loaded when Claude reads a matching file so they shape every edit.
	2. Skills load on-demand as task-style workflows, triggered by explicit invocation or when the model decides the skills description matches the prompt.
	3. For background conventions that should apply every time you edit a file type, path-specific rules are correct; skills are a better fit for multi-step procedures you want Claude to run.

## Anti-Patterns

- Using directory-level CLAUDE.md files for conventions that span many directories.
- Placing all conventions in root CLAUDE.md when they only apply to specific file types.
- Not using glob patterns when test or config files are spread throughout the codebase.
- Creating a CLAUDE.md in every directory instead of using path-specific rules.

## Exam Traps
- When conventions must apply to files spread across 50+ directories (like co-located test files), path-specific rules with glob patterns are correct. Directory-level CLAUDE.md would require a file in every directory.
- Root CLAUDE.md loads for every session. Path-specific rules are more token-efficient because they load only when editing matching files.
- Skills load on-demand as task-style workflows (invocable by user or model); path-specific rules load int context automatically when Claude reads a matching file.
	- The exam test this distinction when asking about automatic, always-on convention loading.
