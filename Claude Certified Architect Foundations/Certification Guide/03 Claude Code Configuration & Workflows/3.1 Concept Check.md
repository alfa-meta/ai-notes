## Key Concepts

1. Three-level CLAUDE.md hierarchy:
	1. User-level (~/.claude/CLAUDE.md): applies only to one developer, NOT version-controlled, NOT shared via git.
		1. New team members cloning the repo do NOT get these instructions.
		2. Use for personal preferences like verbosity or output style.
	2. Project-level (.claude/CLAUDE.md): applies to everyone on the project, version-controlled, shared through git.
		1. Team-wide standards (naming conventions, testing requirements, architecture decisions) belong here.
	3. Directory-level (subdirectory CLAUDE.md): applies when working in that specific directory only. Use for package-specific conventions that differ from the project root.

2. @ Import syntax: references external files from CLAUDE.md for modular organisation.
	1. There is no @import keyword; the directive is @ followed by a path, on its own line.
	2. Allows importing relevant standards per package without duplicating content.
	3. Keeps CLAUDE.md modular rather than monolithic.

3. .claude/rules/ directory: holds topic-specific rule files (testing.md, api-conventions.md, deployment.md).
	1. Alternative to one massive CLAUDE.md.
	2. Each file can optionally have YAML frontmatter with path scoping

4. /memory command: verifies which memory files are loaded in the current session.
	1. It is a diagnostic/debugging tool.
	2. It does NOT trigger loading of configuration files -- configuration loads automatically based on location.

## Anti-Patterns

- Placing team-wide standards in user-level config instead of project-level
- Having one massive monolithic CLAUDE.md instead of splitting into rules/ files
- Not using /memory to debug inconsistent behaviour across sessions
- Duplicating instruction across multiple directory-level files instead of importing a shared file with @


## Exam Traps
- New team member not receiving instructions: root cause is always that instructions are in user-level (~/.claude/CLAUDE.md) instead of project-level.
	- User-level config is NOT shared via git.
- Both .claude/CLAUDE.md and root CLAUDE.md are valid project-level locations.
- Directory-level CLAUDE.md applies when working in that specific directory, not necessarily all nested subdirectories.
- /memory does not trigger loading -- it only reveals what is already loaded.
