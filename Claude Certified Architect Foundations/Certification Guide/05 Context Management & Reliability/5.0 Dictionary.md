# Domain 05 Dictionary — Context Management & Reliability

**Access failure vs Valid empty result** — Access failure = the tool couldn't reach the source (consider retry); valid empty result = the query ran and found nothing (never retry — this IS the answer).

**Aggregate metrics trap** — A high overall accuracy figure (e.g. 97%) can hide catastrophic failure rates on specific document types/segments; always validate by document type AND field, not aggregate alone.

**Ambiguous customer matching** — When a lookup returns multiple possible matches, the only safe response is to ask for additional identifiers — never guess based on recency or activity.

**cache_control breakpoint** — Marker placed at the end of a stable prompt prefix telling the API to cache and reuse that prefix on subsequent requests at reduced cost.

**Calibration curve** — Mapping built from labelled validation data showing what a given self-reported confidence score actually corresponds to in real accuracy, per field type.

**Coverage annotation** — Explicit note in a synthesis output flagging which topic areas are well-supported vs limited/gapped, instead of silently omitting weak sections.

**Content-appropriate rendering** — Synthesis should not flatten everything into one format: financial data as tables, news/narrative as prose, technical findings as structured lists. Forcing a uniform format degrades readability.

**Context degradation** — Not a token-limit problem: the model loses grip on specific earlier findings (reverting to "typical pattern" language) as verbose recent output accumulates and dominates attention.

**Conflict handling (source conflicts)** — When two credible sources report different values, annotate both with full source attribution and let the consumer decide — never arbitrarily select one, average them, or silently pick the "more authoritative" source.

**Crash recovery / structured state manifest** — A file each agent exports recording what's been explored, key findings, current phase, and next steps, so a session can resume after a crash without repeating work.

**Ephemeral cache** — `cache_control` cache type that lasts about five minutes since last use; pays off for bursts of related requests, not content reused hours apart.

**Escalation triggers (three valid)** — Explicit human request (honour immediately), policy exception/gap (not a violation), and genuine inability to make progress after an attempt.

**Failure type** — Structured error classification: transient (may retry), validation (fix input), business (rule violation, no retry), or permission (access denied, no retry without new authorisation).

**Field-level confidence calibration** — Per-field confidence scores from the model, calibrated against labelled ground truth before being used to drive automation-vs-review routing.

**Full conversation history (statelessness)** — The Claude API is stateless; every request must carry the complete conversation history since there's no server-side session state.

**Local recovery for transient failures** — Subagents should retry/fallback locally for transient errors before propagating anything to the coordinator; only unresolved failures get escalated upward.

**"Lost in the middle" effect** — Models attend more reliably to the start and end of long inputs; findings buried mid-context get missed. Fixed structurally (key findings summary up front, clear section headers), not by prompting harder.

**Persistent case facts block** — Structured block of transactional facts (amounts, dates, order numbers, statuses) included in every prompt outside the summarised history — the core fix for the progressive summarisation trap.

**Policy exception/gap vs policy violation** — A gap means the policy is silent on this situation (escalate); a violation has a documented answer already, usually "no" (doesn't require escalation).

**Progressive summarisation trap** — Summarising earlier conversation turns to save tokens systematically destroys exact numerical values, dates, and identifiers that transactional systems need.

**Prompt caching** — Marking a stable prompt prefix with a cache breakpoint so the API reuses the already-processed prefix on later requests at a fraction of the cost; requires static content first, volatile content after the breakpoint.

**Reviewer capacity prioritisation** — Route the highest-uncertainty items to human reviewers first, dynamically, rather than spreading capacity evenly across all extractions.

**Scratchpad file** — File where an agent writes key findings during exploration so they persist outside conversation context, immune to context degradation.

**Self-reported confidence score (anti-pattern)** — Unreliable escalation/routing signal because LLM confidence is poorly calibrated — confidently wrong on hard cases, hedging on easy ones.

**Sentiment-based escalation (anti-pattern)** — Unreliable escalation trigger because customer frustration doesn't correlate with case complexity.

**Silent suppression (anti-pattern)** — Returning empty/failed results marked as success; the worst anti-pattern because the coordinator believes the operation succeeded and never retries or escalates.

**Stratified random sampling** — Ongoing human verification sampled across document type, confidence band, and field type — crucially including HIGH-confidence (automated) items, to catch novel error patterns before they go undetected.

**Structured claim-source mapping** — Every finding in a multi-agent research system must carry its provenance: claim, source URL, document name, relevant excerpt, and publication date. Attribution dies during summarisation unless synthesis agents are explicitly instructed to preserve these mappings.

**Structured error context** — Four required elements when a subagent fails: failure type, what was attempted, partial results gathered, and potential alternative approaches.

**Subagent delegation (context isolation)** — Delegating specific investigation questions to subagents so their verbose exploration output stays in their own isolated context instead of polluting the main agent's.

**Summary injection between phases** — Injecting a summary of Phase 1 findings into Phase 2 subagent prompts to avoid duplicated "cold start" exploration.

**Temporal awareness** — Different publication/data-collection dates can explain different reported numbers rather than signalling a contradiction (e.g. 8% growth in 2023 vs 12% in 2024 may just be an accelerating trend); require dates in structured outputs to enable correct interpretation.

**Tool result trimming** — Stripping verbose tool outputs (e.g. 40+ fields down to 5 relevant ones) before they enter conversation history, ideally in a `PostToolUse` hook.

**Upstream agent optimisation** — Having upstream agents return structured key facts/citations instead of verbose raw reasoning chains, so downstream agents with limited context budget aren't wasting tokens.

**Workflow termination (anti-pattern)** — Killing an entire multi-agent pipeline because one subagent failed, discarding completed work from the others; correct response is structured error propagation and continuing with partial results.

**/compact** — Command that summarises a long session to free context; should be used proactively during extended exploration, not just when limits are hit.
