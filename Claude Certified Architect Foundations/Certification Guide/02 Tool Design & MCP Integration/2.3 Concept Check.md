

## Key Concepts

1. Giving a single agent 18 tools degrades selection reliability because decision complexity increases with every additional tool.
	1. The optimal range is 4-5 tools per agent, scoped to that agent's specific role.
	2. A synthesis agent should NOT have web search tools.
	3. A web search agent should NOT have document analysis tools.
	4. Agents with tools outside their specialisation tend to misuse them.
2. Two different fixes for an oversized toolkit: split or consolidate.
	1. If the tools are genuinely different jobs (query, transform, export), split them across role-scoped agents.
	2. If they are variations on one job sharing a shape, consolidate them into a single parameterised tool: 19 near-identical transformation tools collapse into one `transform_data` with an operation parameter.
	3. Consolidation reduces how many tools the agent chooses between; it does not hand the agent new powers, so it does not undo least privilege.
	4. Watch the tension with concept 4 below, which pulls the other way.
	5. Server boundaries are invisible to the model, so a 22-tool problem split across two servers is still a 22-tool problem
3. The "tool_choice" configuration, Three modes exist:
	1. "auto" (default): the model decides whether to call a tool or return text. Use for general operation.
	2. "any": the model MUST call a tool but chooses which one. Use when you need guaranteed structured output from one of multiple schemas
	3. Forced selection {type: "tool", name: "extract_metadata"}: the model MUST call this specific named tool.
		1. Use to enforce mandatory first steps - the model cannot skip or reorder the required operation.
4. Scoped cross-role tools. When an agent frequently needs a capability from another role, routing every request through the coordinator adds 2-3 round trips and up to 40% latency.
	1. The solution: give the agent a scoped, constrained version of the capability for simple cases.
	2. Example: a synthesis agent gets a scoped verify_fact tool for simple single-source lookups, while complex multi-source verification still route through the coordinator.
