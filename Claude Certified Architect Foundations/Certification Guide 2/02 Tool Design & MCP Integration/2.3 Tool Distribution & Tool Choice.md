
Agents Tools - functions it can call.
Tool Selection - is the model's choice of which one to call.
Tool Distribution - is the choice of which agent in a multi-agent system holds which tools.
The number of tools an agent holds directly affects how reliably it selects the right one.

## The Tool Overload Problem

Giving a single agent 18 tools degrades selection reliability.
Every additional tool adds decision complexity, so error rates climb as the toolkit grows.
Keep each agent's set small and scoped to its role.


Relevance matters as much as quantity.
An agent given tools outside its specialisation tends to misuse them.
With a search tool, it may run its own searches instead of using the results already handed to it.
Each agent must only get the tools its defined role needs.

## Consolidating Near-Duplicate Tools

Splitting by role is the wrong fix when the tools all do the same kind of work.
Twenty-two tools become four, and nothing is lost.
Each transformation is now an enum value the model picks inside a single call, not a tool to find among nineteen near-identical descriptions.
Selection accuracy improves because the hard choice got smaller, while the capability stayed the same.

## Replacing Generic Tools with Constrained Alternatives

Apply least privilege to tool design.
Each tool must do exactly what the agent needs and nothing more.


## Scoped Cross-Role Tools

Scoped cross-role tool - is a constrained version of the capability, given directly to the agent that needs it.
	High-frequency simple requests use it.

Complex cases, which need multiple sources, cross-referencing or real judgement, still route through the coordinator.


## The `tool_choice` Configuration

`tool_choice` - `type: auto` - the model decides whether to call a tool or return text.
	Use it for general operation, where the model needs flexibility to respond to respond conversationally when no tool call is appropriate.

`tool_choice` - `type: any` - the model must call a tool but chooses which one.
	Use it when you need guaranteed structured output from one of multiple schemas.
	The model always produces a tool call, never plain text.
	Best used on extraction pipelines.

Forced selection - the model must call one specific named tool.
	Use it to enforce a mandatory first step: the model cannot skip or reorder the required operation.

The coordinator holds no domain-specific tools itself.

## Key Concept

Keep each agent's tools few and scoped to its role.
Scoped cross-role tools spare high-frequency simple operations the coordinator round trip.

## Exam Traps

### Routing all simple verification through the coordinator when 85% are simple lookups

Coordinator round-trips add 2-3 extra hops per request.
A scoped verify_fact tool on the synthesis agent handles the 85% simple case directly, cutting latency by up to 40%

### Using tool_choice 'auto' when structured output is required

With 'auto', the model may return conversational text instead of calling a tool.
The exam guide says 'any' guarantees a tool call and forced selection a specific one.
Current docs say some models reject both and point to 'auto' with strict tool use.

### Giving an agent 18 tools and expecting reliable selection

Every additional tool adds decision complexity, so selection reliability degrades.
Split tools by role into small sets, as the guide's 18 against 4-5 shows.
Current docs place the degradation point at 30 to 50 tools.

### Giving a subagent a generic fetch_url tool for loading documents

Generic tools enable misuse.
Constrained alternatives (load_document that validates document URLs only) enforce the principle of least privilege and make the tool's purpose clearer.
